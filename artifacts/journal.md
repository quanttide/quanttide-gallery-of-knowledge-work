# 日志

## 目标

日志按时间线索传递上下文：记录每个时间点发生了什么（状态变化、决策、事件），使任何时点的上下文可回溯。它回答"这段时间发生了什么"，不回答"现在该怎么做"——后者由 context（语境）承担。

## 与 context 的分工（2026-09-10 起）

- **context 驱动**：执行工作的背景设定（规则、阶段、边界）住在 context 仓库，系统干活时读它
- **journal 传状态**：记录状态变化与事件（"今天做了 X、规则改为 Y、进入了 Z 阶段"），指向当时生效的 context
- 迁移规则：journal 中沉淀出的稳定规则移入 context；journal 保留一次性事件与快照

## 流程

1. 捕获：随时把信息和想法记入日志，不求条理与准确，先写下来。
2. 整理：定期（如每日或每周固定一次）编辑日志，把零散内容整合得更有条理、更准确。
3. 分流：把整理后的内容写入对应的目标文档，一篇内容只转出一个明确去处。**其中稳定规则类内容转入 context（驱动），事件类转档案/洞察/路线图，暂无归宿进材料暂存区（profile/iGuo/default.md）。**
4. 清空：已转出的内容从日志中删除，暂无去处的想法保留原位，等待下一次整理。

## 验收

- 每次整理后日志明显缩短，已转出的内容不留副本。
- 每篇转出的内容在目标文档中有明确去处，可被再次找到。
- 阻塞期间记录的想法在日志中可追溯，未因等待而丢失。
- **驱动规则不在日志中：新会话读 context 即可获得执行所需上下文，无需翻日志历史。**
