# 从主体到领域

## 目标

把法人主体第二大脑里属于某领域的文档迁入该领域第二大脑：按性质定资产、按同构定落点，迁移全程内容至少在一处，上游净缩短。

## 步骤

1. 筛候选：用目录层按名字与路径的领域段筛出候选——只凭目录，不读正文，产出候选清单供圈定。
2. 定性质：读正文判断它是哪件资产（洞察、规格、手册、原型设计……）。判据是它讲什么，不是它现在住在哪个目录。
3. 定落点：目标位置与源位置同构——源在 `examples/` 的也进实验室，源是洞察的进 `data/insight`；文件名与标题沿用目标侧的命名规则。
4. 写目标：先在目标仓写就、提交、推送——先写后删，不留两边都空的窗口。
5. 删源：源侧各子仓库分别提交推送，上游净缩短。
6. 断链：指向留在原地文档的相对链接删去，不做跨仓库链接补丁；来源与锚点保留文字。
7. 指针：逐层更新——源侧子仓库 → 主体仓库 → 根仓库；目标侧子仓库 → 领域仓库 → 根仓库。
8. 复核：刷新目录层快照，两边对账，并确认源侧已搜不到该文档。

## 验收

- 迁移期间任一时刻，文档至少在一处可找到。
- 目标侧落点与资产类型一致，且与源侧位置同构，命名沿用目标侧规则。
- 源侧不留副本、不留指引行——git 历史即移动凭证。
- 目标侧无指向源侧文档的相对链接。
- 目录层复核：目标侧索引收录该文档，源侧索引已无该文档，两个第二大脑对账通过。
